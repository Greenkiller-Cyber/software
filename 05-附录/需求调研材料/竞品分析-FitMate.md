## 1 调研目的与问题

### 1.1 要回答的问题

在决定做 FitMate 之前，需要确认三件事：

1. 市面上是否已经有人把"计划 → 执行 → 反馈"闭环做完了？（如果做完了，选题价值就低）
2. 现有产品的短板具体在哪一环？（决定我们的差异化落点）
3. 这些短板是**产品定位取舍**造成的，还是**技术难度**造成的？（决定我们能不能在 14 周内做出差异）

### 1.2 分析框架

对每款产品问五个问题，形成统一的可比维度：

| 编号 | 问题 | 对应能力 |
|------|------|---------|
| Q1 | 训练计划从哪来？是用户自己想的、系统生成的，还是买课得来的？ | 计划生成能力 |
| Q2 | 记录做到多细？能不能记到"第 3 组 80kg×8 RPE8"？ | 记录粒度 |
| Q3 | 练完之后，产品告诉你什么？只有总数还是有趋势与结构分析？ | 数据反馈 |
| Q4 | 教练在哪里？是只能买课，还是能基于我的数据给建议？ | 教练协作 |
| Q5 | 换器械、换目标、停练两周之后，计划会跟着变吗？ | 计划适应性 |

## 2 竞品选择与定位

| 产品 | 类型 | 选择理由 |
|------|------|---------|
| **Keep** | 内容型综合运动平台（国内） | 国内最大众的运动入口，代表"内容+社区"路线，是用户默认对照物 |
| **Strong** | 纯训练记录工具（海外） | 力量训练记录的标杆产品，代表"极简记录"路线 |
| **Hevy** | 记录 + 社交 + 教练端（海外） | 代表"记录 + 社区 + 教练服务"的进阶形态，最接近我们要做的方向 |
| **训记** | 力量训练记录（国内） | 国内力量记录类代表，用来验证"中文记录工具"的成熟度 |

> 选择原则：覆盖**内容路线**（Keep）、**工具路线**（Strong / 训记）、**社区 + 教练路线**（Hevy）三类典型形态，避免只挑弱对手。

## 3 逐款分析

### 3.1 Keep

**定位**：以课程内容和社区为核心的运动健身平台，覆盖健身、跑步、瑜伽、骑行等。

**核心流程**：选课程/计划 → 跟练视频 → 打卡 → 社区分享 →（部分内容）会员付费。

**优点**

- 内容量大，跟练体验成熟，适合"不知道练什么、跟着做就行"的新手
- 社区氛围与激励机制（徽章、排行榜、挑战）做得完整
- 中文生态完善，国内可直接使用

**不足**

- **计划是"课程编排"，不是"按我的器械条件和目标生成"**：用户想在家用哑铃练，仍要在课程库里自己筛
- **记录粒度粗**：以"完成课程/打卡"为单位，难以记录"第 3 组 80kg×8"
- **数据反馈偏"做了多少"，而非"强了多少"**：缺少容量、力量曲线、肌群平衡这类结构分析
- 教练是付费服务的一部分，无法让"我自己的教练"基于我的数据给建议

**对我们的启示**：内容不是我们的战场（版权与制作成本高），**计划生成与数据反馈才是空白**。

### 3.2 Strong

**定位**：极简的力量训练记录工具，核心是"快速记录每一组"。

**核心流程**：建 routine（例程）→ 开始训练 → 逐组记录重量/次数 → 休息计时 → 完成 → 查看历史。

**优点**

- 记录体验极佳，单手操作、离线可用，训练中不打断节奏
- 历史数据与图表（最大重量、总容量）可靠
- 数据可导出，用户资产归属清晰

**不足**

- **不生成计划**：routine 要用户自己建，新手照样不知道"今天该练什么、练几组"
- **无周期化**：没有"4 周一个周期、第 3 周减量"这类阶段管理
- **几乎无社交**：一个人练，缺少反馈与督促
- **无教练环节**：数据在自己手机上，教练看不到

**对我们的启示**：记录做深是对的，但**"记录 + 计划生成"之间的断点**正是机会。

### 3.3 Hevy

**定位**：训练记录 + 社交 + 教练协作，免费功能较多，走"健身版社交工具"路线。

**核心流程**：选/建 routine → 记录 → 发布训练动态 → 关注他人 → 查看进度图表。

**优点**

- 记录能力接近 Strong，同时补上了社交与进度可视化
- routine 模板可复用、可分享，降低"不会编排"的门槛
- 近年向教练侧延伸（面向私教的教练端服务），说明"数据 + 教练"是行业认可的方向

**不足**

- **模板是"社区共享"，不是"按我的条件生成"**：器械、频率、伤病史仍需自己判断
- 教练端是**独立的商业产品**，普通用户与自己的教练之间仍缺少"授权即协作"的轻量通道
- 中文与国内网络环境支持一般，教练资质审核等本地化合规能力缺失

**对我们的启示**：方向对，但**"授权式轻量教练协作"**这一层在国内大众产品里仍是空白。

### 3.4 训记

**定位**：面向力量训练者的中文记录工具，强调记录效率与模板。

**核心流程**：建动作/模板 → 记录组次 → 查看历史与统计。

**优点**

- 中文界面，记录粒度细（重量、次数、组数），符合力量训练习惯
- 模板化程度高，重复训练日可快速复用
- 无社交干扰，专注记录

**不足**

- **无计划生成**，模板仍需用户自己设计
- **无周期化与教练协作**
- 数据统计偏"总量与历史"，缺少肌群结构分析
- 社区与激励弱，长期坚持靠自律

## 5 关键发现（Gap 分析）

### 发现 1：内容型产品解不了"个性化"，工具型产品解不了"从 0 到 1"

- Keep 强在"给你内容"，弱在"内容适配我"；
- Strong / 训记 强在"记录我做了啥"，弱在"告诉我该做啥"。

二者之间的空档：**用户有能力自己练，但缺少一份适配自身条件的计划，以及练完之后的解释**。

### 发现 2：教练不是没有，而是"接不上"

现有产品的教练要么是平台雇佣的付费服务（Keep），要么是面向私教的独立商业工具（Hevy Coach）。而现实中大量用户的情况是：

> "我有个朋友/健身房教练愿意帮我看，但他看不到我的数据，只能靠我截图。"

这是我们判断最值得做的一环：**授权式轻量协作** —— 用户主动勾选"允许该教练查看哪段时间、哪些数据"，教练在授权范围内点评与调整。

### 发现 3：记录粒度与统计口径脱节

工具类产品记录很细（组次重量），但统计往往只给"总容量"或"最高重量"两个数。真正反映训练结构的是：

```
容量（tonnage）   = Σ(重量 × 次数 × 组数)
肌群占比         = 某肌群容量 / 总容量
周期达成率       = 实际完成训练次数 / 计划次数
```

这些指标现有产品普遍缺失或需手工导出计算 —— **统计口径本身就是产品差异点**，也是 C4 场景的落点。

### 发现 4：易变的是内容，稳定的是"计划 + 数据 + 反馈"

内容型产品需要持续产出课程（重资产），记录型产品只要把数据模型打磨好就能长期可用。对个人 14 周的项目来说，**后者才是可交付的**。

## 6 目标用户与典型场景（基于上述分析提出的假设）

> 说明：以下为分析推导出的用户假设，**待第 4 周后通过问卷/访谈验证**（见第 8 节）。

### Persona 1：自学型训练者（主力用户）

- 特征：训练 6–24 个月，能看懂动作，但计划靠网上抄
- 痛点：抄来的计划器械不匹配；换健身房后计划失效；不知道强度够不够
- 期望：输入条件 → 得到一份能执行 4 周的计划 → 练完看到进步

### Persona 2：带训教练（差异化角色）

- 特征：健身房私教或资深训练者，带 5–20 名学员
- 痛点：学员数据靠截图/口头；没法批量看谁掉队；给建议效率低
- 期望：学员授权后，一屏看到学员本周执行情况，直接给点评

### Persona 3：平台管理员（合规角色）

- 需求：审核模板与教练资质、看运营聚合数据，但**不应看到用户训练明细**

### 关键场景（对应需求 ID）

| 场景 | 说明 | 对应 FR |
|------|------|---------|
| 生成计划 | 填目标/器械/频率 → 得到 4 周计划，动作全部匹配可用器械 | FR-03, FR-09 |
| 执行打卡 | 训练中逐组记录，休息计时，完成后打卡 | FR-13 ~ FR-15 |
| 看进步 | 查看容量趋势、主要动作力量曲线、肌群是否偏科 | FR-21 ~ FR-23 |
| 教练点评 | 学员授权 → 教练看本周数据 → 给调整建议 → 学员收到通知 | FR-17 ~ FR-19, FR-26 |
| 审核上架 | 教练提交模板 → 管理员审核 → 通过后进入模板库 | FR-08, FR-28 |

## 7 差异化定位与设计原则

**定位一句话**：不是"又一个记录工具"，也不是"又一个课程平台"，而是**把"计划生成—执行记录—数据反馈—教练调整"接成闭环的自助训练助手**。

| 设计原则 | 含义 | 落到哪个需求 |
|---------|------|-------------|
| P1 计划必须"可执行" | 生成的动作必须在用户器械条件内，否则宁可少生成 | FR-03, FR-09 |
| P2 记录必须"不打断训练" | 训练中三步内完成一组记录，否则用户会放弃 | FR-13, FR-14 |
| P3 反馈必须"可解释" | 不只给数字，要给"你这个月推的力量涨了、腿练少了"这类结论 | FR-21 ~ FR-23 |
| P4 教练必须"被授权" | 默认不可见，用户显式授权后可见，且可随时收回 | FR-04, FR-18 |
| P5 审核必须"留痕" | 模板与资质审核记录审核人、意见、时间 | FR-08, FR-17 |

**明确不做**（与竞品的边界）：不做课程视频（版权成本）、不做社交动态（社区是另一领域）、不做支付计费（本期不涉钱）。

| 编号 | 假设 | 验证方式 | 时间 |
