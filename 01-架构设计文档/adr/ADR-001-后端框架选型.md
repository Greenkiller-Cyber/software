# ADR-001：后端框架选型

- 日期：2026-11-23
- 状态：已接受
- 涉及视图：开发 / 运行

## 背景

系统需要实现 7 个业务模块、约 30 个接口，并具备 JWT 鉴权、定时任务、消息消费、事务管理等基础能力。开发者为单人，14 周课余时间，其中编码窗口约 8–10 周。课程要求真实后端 + 真实数据库，且需交付 OpenAPI 文档与单元测试。

约束：

1. 只有一个人，主要技术积累在 Java / Spring 生态；
2. 部署环境是单台 2 核 4G 服务器，不能承担重型中间件运维；
3. 鉴权、事务、调度、消息客户端需要成熟方案，避免自研。

## 备选方案

| 方案 | 优点 | 缺点 |
|------|------|------|
| A：Spring Boot 3（Java 17） | 生态最全（Security、AMQP、Scheduler、Validation 开箱即用）；依赖注入天然适配四层分层；社区资料多，排错成本低 | 启动约 2–3s；内存占用高于 Go；板式代码略多 |
| B：NestJS（Node 20 + TS） | 与前端同语言，DTO 类型可复用；模块化设计优雅 | 本人不熟 TS 后端生态；复杂聚合查询不如 SQL 直接 |
| C：Django + DRF（Python） | 开发最快，自带 Admin 后台 | 并发模型弱（GIL）；本人无 Python 工程经验；与课程参考栈不一致 |
| D：Go + Gin | 性能好、内存占用低 | 生态薄（鉴权/校验需自拼）；开发效率最低，14 周风险高 |

## 决策

采用 **Spring Boot 3 + Java 17**：持久层 MyBatis-Plus，鉴权 Spring Security + JWT，消息 Spring AMQP。

## 理由

1. **熟悉度决定 14 周成败**：单人项目最大风险是时间而非性能，选最熟的栈可把精力留给架构与领域逻辑。
2. **生态覆盖全部非功能需求**：鉴权、校验、调度、消息、监控均有官方 starter，无需自研。
3. **放弃的代价**：NestJS 的语言统一优势抵不过我不熟后端生态的试错成本；Django 的 Admin 对本项目的审核状态机收益有限；Go 的性能优势在 DAU 2000 下无意义。
4. **自身代价**：启动慢、内存 300–500MB（4G 单机够用）；板式代码通过代码模板（Skill 的 templates/）缓解。

## 影响

- **开发视图**：目录按四层组织，与 Spring 包扫描配合；`@Transactional` 只允许出现在 application 层（写入 §5.7 与 Skill 强制约束）。
- **运行视图**：JVM `-Xmx1g`，单实例；定时任务用 `@Scheduled` + 分布式锁（本期单实例，预留多实例）。
- **物理视图**：镜像基于 `eclipse-temurin:17-jre-alpine`，约 250MB。
- **风险**：Spring Boot 3 要求 JDK 17+，需确认部署环境版本。

## 验证方式

1. 第 11 周若核心链路（生成计划 + 打卡）能在 800ms 内完成，则决策成立；
2. 若 MyBatis-Plus 在复杂统计 SQL 上表达困难，局部降级为原生 MyBatis XML，**不推翻框架**；
3. 仅当常驻内存超 1.5G 或单机 QPS 瓶颈低于 200 时才重新评估（届时优先垂直扩容，不换栈）。

## 实施记录（2026-11-23）

| 项 | 计划 | 实际 | 结论 |
|----|------|------|------|
| 框架版本 | Spring Boot 3.x | Spring Boot 3.2.3 | 一致 |
| JDK | 17+ | **21（LTS）** | 上调：本机已装 21，不额外安装；Spring Boot 3.2 完全支持 |
| 持久层 | MyBatis-Plus | MyBatis-Plus 3.5.7 | 一致 |
| 数据库迁移 | Flyway | **未引入**，改为手工执行 `db/V1__init.sql` | 偏差：离线仓库无 Flyway 构件；脚本与 §4.2 数据字典已 1:1 对齐，联网后可平移 |
| 构建 | Maven | Maven 3.9.12（本地仓库指向工作区 `.m2-repo`） | 一致 |
| 验证 | 可启动 | `mvn package` 成功（jar 27MB）；无库时应用可启动，`/api/v1/health` 返回 UP；4 个单元测试通过 | 决策成立 |

**未出现需要推翻决策的信号。** 唯一实质偏差是 Flyway 缺失，属于工具链而非框架问题，处理方式是"脚本入库 + 文档锁定字段"，与任务书「ER 图与实际建表脚本必须一致」的要求不冲突。
